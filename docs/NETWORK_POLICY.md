# Локальные файлы и сеть OpenFrame

Разрешён единственный сетевой адрес: числовой IPv4 `127.0.0.1`. `localhost`, другие адреса 127/8, IPv6 `::1`, IPv4-mapped IPv6, DNS-имена и proxy не входят в разрешённый набор.

## Реализованные ограничения

`ApiServer` вызывает `QTcpServer::listen(QHostAddress("127.0.0.1"), port)` и устанавливает `NoProxy`. Входящие peer addresses дополнительно проверяются как IPv4 и точное совпадение. Приложение не инициирует сетевых соединений с Maya: адаптер создаёт `socket(AF_INET, SOCK_STREAM)` и соединяется с неизменяемым `127.0.0.1`, используя только порт из проверенного endpoint. Host endpoint проверяется до создания socket. DNS/getaddrinfo, HTTP-клиенты, browser launch, telemetry, updater и удалённое исполнение отсутствуют в интеграции.

API аутентифицируется случайным token из приватного пользовательского каталога. Ограничены размеры, частота, число соединений и время простоя. Конверт и каждый метод имеют явный список ключей и типов; неизвестная команда не передаётся внешнему интерпретатору. Token не записывается в обычные диагностические отчёты. Это защита от других локальных пользователей и случайных клиентов; код, уже выполняющийся с правами того же пользователя, имеет доступ к его endpoint.

## Политика путей

`LocalPathPolicy` применяется ядром, медиадекодером, экспортом, проектным/CSV API. Python-адаптер повторяет проверки для endpoint и playblast. Отклоняются:

- URL и protocol names, включая `file:`, UNC `\\host\share`, device namespaces `\\?\` / `\\.\`, drive-relative `C:file` и alternate data streams;
- управляющие символы, неоднозначные Windows-компоненты и имена устройств;
- сетевые и substituted drives, недоступные или неопознанные типы дисков;
- **все** symlinks/reparse points, в том числе локальные; это намеренно более строгая политика;
- буквальные `..` в пути: нормализация до проверки могла бы скрыть reparse-компонент;
- отсутствующие промежуточные каталоги; для вывода допускается только отсутствующий конечный файл/новый конечный каталог.

Windows-проверка обходит компоненты по одному через `CreateFileW(FILE_FLAG_OPEN_REPARSE_POINT | FILE_FLAG_BACKUP_SEMANTICS)` и проверяет атрибуты открытого объекта, не следуя последнему reparse target. Root drive проверяется до обхода через GetDriveType/QueryDosDevice. Поэтому заранее существующий junction на сетевой путь отклоняется до обращения к target. Вложенные source/sequence paths при загрузке проекта проверяются отдельно; строка локального project filename не делает безопасными его ссылки.

Медиадвижок использует собственный файловый AVIO и отклоняет вложенные открытия demuxer/muxer. Сетевые протоколы и manifests не должны обходить эту границу. Для поставляемого FFmpeg требуется отдельная сборка с `--disable-network` и отключёнными network dependencies/protocols. Конкретные флаги, версия и хеши готовой сборки фиксируются её build manifest; наличие проверок на уровне приложения не заменяет проверку этого manifest. Основа: [FFmpeg configure](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/configure).

Новая последовательность изображений сначала записывается во временный соседний каталог. Публикация в существующий каталог проверяет каждый конечный путь. Без явного overwrite коллизии отклоняются; с overwrite заменяемые файлы сначала резервируются и восстанавливаются при ошибке или отмене публикации. Посторонние файлы каталога сохраняются. Видео/аудио публикуются через QSaveFile после завершения кодирования. Отмена не выдаёт промежуточный файл за завершённый результат.

Справочные источники: [Win32 reparse points](https://learn.microsoft.com/en-us/windows/win32/fileio/reparse-points), [CreateFileW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew), [GetDriveTypeW](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getdrivetypew), [QTcpServer](https://doc.qt.io/qt-6.8/qtcpserver.html).

## Воспроизводимые отрицательные проверки

`openframe_api_tests` проверяет реальный C++ сервер: адрес endpoint, разрешённый authenticated localhost round trip, неверный token и закрытие socket, неизвестные команды/поля/типы, запросы чрезмерного размера и частоты, URL/UNC/output-path отказ. На Windows создаётся собственный symlink на недоступный синтетический UNC target и проверяется отказ без чтения target. Если ОС запрещает создание symlink, тест явно сообщает SKIP; это не засчитывается как проверка reparse.

`test_maya.py` подменяет DNS resolver на функцию, немедленно завершающую тест ошибкой, и задаёт HTTP_PROXY/ALL_PROXY на документационные внешние адреса. Успешный локальный round trip в этом окружении проверяет, что клиент не использует эти маршруты. Endpoint с localhost/127.0.0.2/::1/внешним адресом отклоняется до создания сокета. Проверяются лексические запрещённые пути до filesystem API и локальная symlink-цепочка. Медиатесты ядра отдельно проверяют вложенные URL/manifests.

Для доказательства поведения готовой поставки нужен отдельный трассировочный прогон: зафиксировать хеш exe/DLL, PID дерева процессов, окружение proxy и включить Windows ETW/WFP либо эквивалентный packet/socket trace **до** запуска. Выполнить запуск, локальный импорт, отказ URL/UNC/manifest, декодирование/seek/playback, экспорт, отмену, Maya reconnect и завершение. Проверить TCP/UDP/DNS-события каждого собственного процесса; разрешены только соединения 127.0.0.1↔127.0.0.1. Отдельно проверить отсутствие IPv6 и DNS, а не только отсутствие установленных TCP-соединений в одном снимке. Артефакты трассы и команды должны храниться в test-results конкретной сборки.

20 ноября 2026 проверена доступность `Microsoft-Windows-Winsock-AFD`: провайдер обнаружен, но запуск временной ETW-сессии из текущего токена завершился `0x80070005 Access is denied` с требованием administrator. Сессия не была создана; успешная трассировка не заявляется. Журнал проверки доступности: `test-results/network-trace-availability.json`. Это ограничение прав Windows, а не отказ проверки разрешений Codex.

Unit/integration tests и отсутствие событий в одном моментальном снимке не доказывают полной изоляции всей системы. Между проверкой пути и использованием есть обычные filesystem TOCTOU-границы; гарантия против враждебного процесса того же пользователя требует OS-level containment. Здесь не заявляется контроль сетевого поведения Windows, драйверов или сторонних плагинов Maya. Производственный целевой путь проверки — Windows; эквивалентная изоляция всех сторонних файловых драйверов других ОС отдельно не подтверждена.
