# OpenFrame — результаты приёмки

Дата: 20 ноября 2026 года. Цель полного соответствия из [ТЗ](SPECIFICATION.md) сохранена. **Рабочая независимая реализация создана; полное соответствие Keyframe Pro 2 не подтверждено.** Самостоятельные проверки ниже не подменяют сравнительные тесты оригинала.

Установленный эталон зафиксирован как **Keyframe Pro 2 1.7.1**, см. [REFERENCE.md](REFERENCE.md). Новая проверенная поставка — **OpenFrame 0.4.0** в `dist/OpenFrame-0.4.0`: [отдельная приёмка](ACCEPTANCE_0_4_0.md), [численные результаты и хеши](VALIDATION_0_4_0.json), [реестр требований](REFERENCE_1_7_1_MATRIX.md). В ней есть измеренное ограничение скорости HDR CPU. Предыдущий пакет 0.3.0 сохранён в `dist/OpenFrame`: [приёмка 0.3.0](ACCEPTANCE_0_3_0.md), [приёмка 0.2.0](ACCEPTANCE_0_2_0.md).

**Ниже сохранена история проверки OpenFrame 0.1.0.** Её результаты не переносятся автоматически на последующие изменения. Доказательства каждой новой поставки относятся к указанному в её отчёте SHA-256.

## Поставка и воспроизводимость

Исходники находятся в каталоге OpenFrame, переносимая программа — в `dist/OpenFrame/OpenFrame.exe`. Собственный код — MIT. Устанавливать Python, Maya или SDK для проигрывателя не требуется; библиотеки Qt, FFmpeg и C++ поставляются рядом. `build-info.json` содержит версии зависимостей и SHA-256 каждого EXE/DLL.

Зафиксированная сборка **0.1.0**, SHA-256 EXE: `EDBAE2A0CD87F965A5589743316E0D8367F0119A05474CC5C4C216FF007637AB`. Все 38 EXE/DLL сверены с манифестом. Численная сводка и хеши доказательств: [VALIDATION.json](VALIDATION.json).

Окружение проверки: Windows 11 x64, build 26300; Qt 6.8.3 MSVC x64; собственная динамическая LGPL-сборка FFmpeg 7.1.5; Maya 2024 для настоящей GUI-интеграции. При проверке переносимости PATH ограничен каталогом приложения и Windows, QT_PLUGIN_PATH отсутствует. Загруженные библиотеки Qt/FFmpeg сверяются с каталогом пакета.

Для сборки и повторения проверок используются `tools/build.ps1`, `tools/make_test_media.ps1`, `tools/test_runtime_media.py`, `tools/run_maya_gui_test.ps1` и сценарии в `tests/integration`. Maya GUI-сценарий требует endpoint отдельного тестового экземпляра OpenFrame: он заменяет проект этого экземпляра и создаёт собственную пустую Maya с отдельными preferences. Пользовательские сцены не используются.

Подробные результаты, журналы и собственные снимки находятся в `test-results/` и исключены из Git. Результаты устаревших и неуспешных прогонов сохранены для диагностики; VALIDATION.json ссылается на конкретные успешные артефакты и хеши. Проверки предыдущих кандидатов отделены от проверок окончательного EXE.

## Реализованные группы

| Группа | Что работает в собственной реализации | Граница утверждения |
|---|---|---|
| Медиа и навигация | CFR/VFR/PTS, B-frames, покадровая навигация, forward/reverse, скорости, диапазон, loop/ping-pong, RAM-кэш, audio scrub | Нет утверждения о поддержке каждого формата/кодека оригинала или одинаковой производительности |
| Проект | Источники, папки, несколько таймлайнов, trim/reorder, audio replacement, relink, собственный JSON `.oframe`, объединение проектов | Оригинальный проектный формат пока не реализован |
| Просмотр | A/B, wipe/blend, split/grid, transform, overlays; общий compositor для viewer и экспорта | Пиксельное совпадение с оригиналом не измерялось |
| Аннотации/заметки | FG/BG, рисунок/текст, hold/ghosting, scoped undo, закладки, notes, CSV с multiline/Unicode | Все пограничные особенности оригинала ещё не описаны сравнительными сценариями |
| Экспорт | Видео/аудио/изображения, весь timeline/диапазон/шаг/закладки, source/viewer, audio/annotations, progress/cancel, атомарная публикация, управляемая перезапись sequence | Выходные кодеки ограничены фактической сборкой FFmpeg |
| Maya/API | Два направления, offset/multiplier/range, lifecycle/reconnect, playblast в A/B, независимый Python-фасад | Wire protocol оригинала не реализован; другие версии Maya ещё не проверялись фактически |
| UI | Меню, доки, контекстные команды, настройки, горячие клавиши, локальные диалоги | Собственные UI-тесты и DPI-снимки не доказывают точного совпадения эталона |

Подробная связь команд и настроек с работающими путями: [UI_COVERAGE.md](UI_COVERAGE.md). Архитектурные отличия также перечислены там явно: встроенные libav вместо выбираемого внешнего ffmpeg.exe, аутентифицированный API вместо legacy commandPort, software viewer без фиктивного переключателя backend.

## Проверки медиа и интеграции

- Окончательная сборка прошла **5/5 CTest-наборов**: core, UI, C++ API, Python Maya adapter и реальные FFmpeg capabilities. C++ API — 605 assertions, Python — 21 тест. Подробный прогон core — 33 passed / 0 failed / 0 skipped, включая lifecycle QtTest. Наличие корпуса/аудиоустройства проверяется; SKIP не засчитывается как успешная фактическая проверка.
- Реальный QAudioSink проверялся при обычном воспроизведении, seek, reverse, 2× и 0.5×: устройство активно, ошибка 0, используются аудиочасы; текущий и отображаемый кадр совпадают в записанных срезах. Это проверка программного вывода, не измерение акустической задержки динамиков.
- Сквозной lossless-экспорт из переносимого приложения: 120 кадров при 24 fps, 48 kHz stereo, ровно 240000 PCM samples. Пять видеовспышек стоят на кадрах 0/24/48/72/96. Пороговое начало звуковых импульсов отличается на два сэмпла (0.0417 ms) на этом синтетическом сигнале; это не универсальная оценка всех медиа.
- Собственный проект и CSV проходят roundtrip с кавычками, многострочным русским текстом и заметками.
- Исправлен standalone VFR export: вместо сжатия длительности по `frameCount/fps` используется CFR resampling по исходным PTS с явно выбранной рациональной output FPS. На корпусе 97 исходных кадров превращаются в 120@24 либо 300@60; все 120 RGB-кадров source/timeline совпадают, PCM и диапазон проверены. Matroska округляет последний video interval до 4.999 s, выходное CFR-видео — 5.000 s. Hardware playback источника продолжается после 4.3 s и доходит до последнего кадра по PTS. VFR passthrough не заявляется.
- Исправлены owner/координаты аннотаций в A/B, обоих split, grid, wipe/blend. Проверены разные owners, короткий источник, draft/undo и точное равенство PNG viewer export общему compositor.
- MPEG4/AAC и h264_mf/AAC через реальный C++ API: по 120 кадров, 24 fps, длительность видео 5.000 s. Аудио декодируется и не является тишиной; 240640 samples включают 640 samples / 13.33 ms AAC padding.
- Независимый Python-фасад проходит 55 проверок через настоящий API. С переданным пользователем скриптом Maya 1.5.7 сверены сигнатуры 40 публичных методов; все допустимы для вызова. Три низкоуровневых транспортных метода не входят в этот фасад. Тела оригинальных методов исполнителям не передавались. Совпадение сигнатур не означает совпадения всего поведения или запуска оригинального встроенного клиента без адаптации.
- Входные события FakeMaya 60/120 Hz проверяют coalescing: 180/360 событий, корректный последний кадр, отсутствие ошибок и переподключений, максимум 36 API-запросов/s в этом прогоне. Это не утверждение о 60/120 отрисованных кадрах/s.
- Настоящая GUI Maya 2024 с адаптером из пакета проходит 14 проверок: преобразование времени в обе стороны, диапазон, отсутствие обратного эха, stop/start, создание/закрытие окна, собственный playblast, его импорт и назначение viewer B, восстановление времени Maya. Независимый ffprobe подтверждает rawvideo 320×180, 24 кадра, 24 fps, 1.000 s. Отчёт: `test-results/packaged-runtime-ui2/maya/maya-report.json`.
- Окончательный UI прошёл Windows native backend и offscreen scale 100/125/150/200%. В каждом прогоне: 124 команды, 22 снимка диалогов и два снимка главного окна, доступные кнопки, пригодные шрифты, отсутствие изменения проекта после отмены. Всего 120 снимков. Проверены исправления контраста, picker, статуса, scroll summary и новые output FPS/sparse audio controls. Отчёт: `test-results/ui-validation-summary.json`. Переходы между физическими мониторами с разным DPI не проверялись.
- Добавлены H.264/AAC источники 29.97 и 60 fps длительностью 90.09/90 s с GOP около 30 s и 2022/4047 B-кадрами. Импорт, seek и export хвостов 48/60 кадров прошли; PCM не пустой, частоты и длительности верны. Первый и последний RGB каждого экспортированного хвоста совпали с независимым полным декодированием: MAE/RMSE=0. Отчёт: `test-results/packaged-long-media/long-media-report.json`. API seek здесь проверяет состояние кадра; pixel comparison — экспортное декодирование, а не завершение GUI render.

Артефакты окончательного EXE: `test-results/packaged-final/`, `test-results/packaged-long-media/`, `test-results/ui-validation-summary.json`, `test-results/package-final-vfr-build.log`. Реальная Maya проверялась на кандидате `26252E1A…BD7E4A4` до последнего изменения VFR exporter/FPS controls; Maya adapter с тех пор не изменён. Дополнительные 55 facade checks, MFT codecs и coalescing проверялись на `F69DD70B…15824`; детали и границы переноса этих доказательств явно разделены в VALIDATION.json.

## Установленные различия и границы корпуса

- В OpenFrame pan/zoom видео применяется по панелям; аннотации находятся в нормализованных координатах своей панели и не следуют transform медиапикселей. В [публичном описании Keyframe Pro 2](https://zurbrigg.com/keyframe-pro-2-documentation/kpro2-pan-and-zoom) pan/zoom применяется ко всему viewer, включая split view. Это известное расхождение, которое нельзя выдать за неподтверждённое совпадение.
- Декодирование/compositor используют 8-bit RGBA8888. High-bit-depth/HDR preservation не реализовано; точные color-management и alpha semantics видео не подтверждены. Проверка RGB lossless не доказывает сохранение alpha.
- Корпус содержит короткие ролики 24/23.976 fps и 90-секундные 29.97/60 fps с длинными GOP; 25 fps проверяется на image sequences. Многочасовые проекты, большой набор реальных контейнеров/кодеков и аннотации в очень длинных проектах пока не покрыты.
- Audio transport проверяется короткими отрезками. Hot-plug/смена аудиоустройства во время playback, многочасовой drift, потеря/возврат устройства и длительные loop/ping-pong сессии ещё не проверены.
- При публикации sequence отдельные файлы заменяются последовательно после полного рендера. Ошибки и отмена откатываются, но crash/power-loss recovery в середине публикации не реализовано. Это не единая атомарная операция над каталогом.
- Stepped/bookmark image sequences не создают audio sidecar; UI отключает эту опцию и поясняет ограничение. Непрерывная последовательность может включать audio.wav. Bookmarks-only video отклоняется явно.
- Custom/image overlays и другие документированные функции выбранной 1.7.1 входят в обязательный объём. Их нет в подтверждённом покрытии данной сборки 0.1.0; следующая реализация и проверка учитываются отдельно.

## Ограничение сети

API слушает только числовой IPv4 `127.0.0.1`, Python-клиент соединяется только с ним. Proxy и DNS не используются в интеграции. URL/UNC/network drives/reparse points отклоняются до чтения; вложенные медиассылки также ограничены.

В реальных поставляемых FFmpeg DLL подтверждены `--disable-network`, отключение протоколов по умолчанию и список **только `file,pipe`** для входа и выхода. Отрицательные тесты проверяют адреса, токены, схемы, лимиты, пути, DNS/proxy. В моментальном снимке собственного процесса присутствовал только listener 127.0.0.1, UDP отсутствовал.

Полная ETW/WFP-трасса жизненного цикла пока не выполнена. Снимок сокетов и тесты не объявляются системной изоляцией или доказательством сетевого поведения всей Windows/Maya/драйверов. Подробности и воспроизводимый сценарий трассировки: [NETWORK_POLICY.md](NETWORK_POLICY.md).

## Что остаётся обязательным для заявления о полном соответствии

1. Корпус проектов оригинала и совместимость чтения/записи, включая точную исходную CSV-схему. Пользователь сообщил, что сохранённого проекта пока нет; собственный `.oframe` и гибкий CSV import не закрывают этот пункт.
2. Подтверждение полного режима уже выбранного эталона 1.7.1, перечень всех состояний и сравнительные прогоны функций, хоткеев, мыши, ошибок и недокументированных деталей. До их проведения точные поведение, геометрия и цвета не подтверждены.
3. Оригинальный сетевой протокол, если требуется запуск существующих клиентов без адаптации. Сейчас предоставлены новый протокол и совместимый по публичным вызовам фасад.
4. Полная сетевая трасса, длительные регрессионные сессии, расширенный медиа-корпус и проверка других версий Maya/окружений.

Эти пункты не считаются принятыми расхождениями автоматически. Текущая поставка пригодна для проверки и развития, но завершением полного сравнительного ТЗ пока не называется.
