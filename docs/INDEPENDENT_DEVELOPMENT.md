# Правила независимой разработки

Реализация создаётся по спецификации наблюдаемого поведения, публичной документации и самостоятельно разработанным тестам.

## Разделение ролей

1. Группа исследования описывает интерфейс, входы, выходы и реакции эталона. Использует публичные материалы и обычную работу через интерфейс/API.
2. Группа реализации получает только проверенную спецификацию, разрешённые иллюстрации интерфейса и синтетические тестовые данные.
3. Группа проверки сравнивает результаты двух приложений и оформляет воспроизводимые расхождения.

Исполнители, которым доступны результаты предыдущего анализа бинарников, не должны передавать их группе реализации. Для написания кода используются отдельные контексты без истории такого анализа. Это организационный порядок работы; уже существующую историю общения он не делает изолированной задним числом.

## Допустимые материалы

- Публичная документация и описания API с указанием URL и версии.
- Наблюдения при обычной работе с приложением: действия пользователя, изображения интерфейса, сообщения, результаты экспорта и обмена через документированный API.
- Собственные синтетические ролики, звук, сцены, проекты и тесты.
- Документация используемых открытых библиотек.

Исходники, дизассемблирование, адреса, патчи, внутренние таблицы лицензирования и прежние отчёты обратного анализа стороннего продукта не включаются в спецификацию реализации. Бинарники и ресурсы оригинала не включаются в новый проект.

## Происхождение требований

У каждого требования фиксируются идентификатор, версия эталона, источник, наблюдаемый сценарий, ожидаемый результат и способ проверки. Предположения отмечаются отдельно и не превращаются в подтверждённое поведение без проверки.

Публичные материалы, использованные на этапе подготовки:

- [Keyframe Pro 2](https://zurbrigg.com/keyframe-pro-2)
- [Документация](https://zurbrigg.com/keyframe-pro-2-documentation)
- [Меню](https://zurbrigg.com/keyframe-pro-2-documentation/kpro2-main-menu)
- [Аннотации](https://zurbrigg.com/keyframe-pro-2-documentation/kpro2-annotations)
- [Экспорт](https://zurbrigg.com/keyframe-pro-2-documentation/kpro2-export-to-file)
- [Интеграция Maya](https://zurbrigg.com/keyframe-pro-2-documentation/kpro2-maya-to-keyframe-pro-2-overview)

До публикации фиксируются открытая лицензия собственного кода и условия включения каждой зависимости. Полнота функций, происхождение кода и соблюдение сетевых ограничений проверяются независимо друг от друга.

## Реализация OpenFrame

Для ядра, интерфейса и интеграции были созданы три отдельных контекста без предшествующей истории анализа оригинального продукта. Им переданы это ТЗ, ссылки на публичную документацию и самостоятельно созданные тестовые данные. Координатор занимался сборкой, зависимостями, упаковкой и проверками.

Присланный пользователем `maya_to_keyframe_pro_2.py` версии 1.5.7 исследован координатором отдельно. В проверке совместимости используются имена методов, параметры и значения по умолчанию класса клиентского API. Тела методов, внутренние константы транспорта и ресурсы скрипта не используются для написания приложения и не передавались исполнителям. Сам файл не включён в исходники или дистрибутив. Проверка сигнатур не считается доказательством совпадения поведения или протокола.
