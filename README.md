# OpenFrame

Независимый открытый проигрыватель анимационных референсов для Windows. C++20, Qt 6, FFmpeg; собственный код — [MIT](LICENSE). Активации, trial, updater и телеметрии нет. Интеграция использует числовой `127.0.0.1`.

**Это рабочая самостоятельная реализация. Полное соответствие Keyframe Pro 2 пока не подтверждено.** Совместимость с закрытыми проектами и исходным сетевым протоколом не заявляется. Доказательства проверок и оставшиеся пункты: [приёмка](docs/ACCEPTANCE.md). Целевой объём [ТЗ](docs/SPECIFICATION.md) сохраняется.

## Запуск

В дереве проекта откройте `dist\OpenFrame-local\OpenFrame.exe`; в готовом переносимом каталоге — `OpenFrame.exe`. Рядом с EXE должны оставаться DLL и каталоги Qt plugins. Python, Maya и SDK для самого проигрывателя не нужны. Версии зависимостей и SHA-256 бинарных файлов сохранены в `build-info.json`.

В 0.4.0 добавлены 10/12-bit данные, HDR → SDR, поворот wipe, давление/ластик и таймауты Maya. **HDR 1080p пока не воспроизводится плавно при 24 fps** на измеренном CPU-пути. [Результаты и ограничения 0.4.0](docs/ACCEPTANCE_0_4_0.md).

Перетащите локальное видео или выберите **File → Import File(s)**. Проекты сохраняются в собственный JSON-формат `.oframe`; медиа остаются отдельными файлами. Раскладка, настройки и сочетания клавиш сохраняются отдельно от проекта.

## Возможности

- Источники, папки, несколько таймлайнов, перестановка/обрезка клипов, подмена аудио, relink, сохранение и объединение проектов.
- Покадровый просмотр, VFR/B-frames, перемотка и обратное воспроизведение, скорость с сохранением высоты звука, диапазон, loop/ping-pong с задержкой и пустым кадром, RAM-кэш, звук/audio scrub, выбор аудиодорожки и её временное смещение.
- A/B, wipe, прозрачность, горизонтальное/вертикальное сравнение и сетка; общий pan/zoom с сохранением по источнику/таймлайну, поворот/отражение, настраиваемые оверлеи, собственные фигуры и растровые изображения.
- Закладки кадров/диапазонов и фильтры заметок/рисунков, рисунки/текст, foreground/background, hold/ghosting, пипетка цвета, временный лазерный указатель, заметки, CSV, undo/redo.
- Экспорт видео, аудио и изображений: весь таймлайн или диапазон, исходный материал или viewer, аннотации, шаг/закладки, прогресс/отмена.
- Локальный API и Maya: оба направления синхронизации, offset/multiplier, диапазон, reconnect, playblast в A/B в виде ролика со звуком или без него и последовательности PNG.

Конкретный набор кодеков определяется поставляемым FFmpeg. FFV1/PCM в MKV используется для проверок без потерь. VFR-видео экспортируется с постоянной выбранной частотой, с выбором кадров по исходным PTS. Stepped/bookmark image sequences экспортируются без аудиофайла; обычная последовательность поддерживает audio.wav. Наличие кодека в другой установке FFmpeg не делает его доступным в OpenFrame.

## Maya

Запустите OpenFrame и выполните в Python-вкладке Maya Script Editor:

```python
import sys
sys.path.insert(0, r"D:\Work\tools\openframe\dist\OpenFrame-local\maya")
import openframe_maya
openframe_maya.show()
```

Выберите экземпляр, подключитесь и включите направление синхронизации. По умолчанию направление **Off**. Startup scripts, shelves, commandPort и глобальные настройки Maya автоматически не меняются. [Инструкция и формулы](docs/MAYA.md).

## Сборка

Нужны Visual Studio 2022 C++ x64, CMake 3.24+, Ninja, Qt 6.8.3 MSVC x64 (qtbase/qtmultimedia, Qt Test для тестов) и FFmpeg 7.1.5 SDK из собственной сборки без сети. [Версии и хеши](tools/dependencies.json).

Запустите **`Build.bat`** двойным щелчком. Он выполняет сборку, тесты и упаковку; готовый EXE — `dist\OpenFrame-local\OpenFrame.exe`. В конце окно остаётся открытым, чтобы можно было прочитать результат. Используется встроенный Windows PowerShell; PowerShell 7 также поддерживается при прямом запуске `tools/build.ps1`.

Пути SDK берутся из параметров, затем `OPENFRAME_QT_ROOT` / `OPENFRAME_FFMPEG_ROOT`, затем `build/CMakeCache.txt` предыдущей сборки. Зависимости автоматически не скачиваются. Для первой сборки на другом компьютере задайте пути явно:

```bat
Build.bat -QtRoot "C:\SDK\Qt\6.8.3\msvc2022_64" -FfmpegRoot "C:\SDK\ffmpeg-local"
```

Дополнительные параметры передаются в `build.ps1`, например `Build.bat -SkipTests` или `Build.bat -PackageDirectory "D:\OpenFrame Build"`. Упаковка включена самим BAT; `-Package` добавлять не нужно. При запуске с параметрами паузы в конце нет, код возврата сохраняется. Эквивалентный прямой запуск:

```powershell
.\tools\build.ps1 -QtRoot C:\SDK\Qt\6.8.3\msvc2022_64 `
  -FfmpegRoot C:\SDK\ffmpeg-local -Package
```

FFmpeg собирается из опубликованных исходников через [build-ffmpeg.sh](tools/build-ffmpeg.sh) в MSYS2 с окружением MSVC x64. Используются динамические LGPL-библиотеки, `--disable-network`, отключённые по умолчанию протоколы, разрешённые только `file,pipe`. [verify_ffmpeg.py](tools/verify_ffmpeg.py) проверяет реальные DLL.

Перед медиатестами создайте собственные сигналы:

```powershell
.\tools\make_test_media.ps1 -Ffmpeg 'C:\Program Files\ffmpeg\bin\ffmpeg.exe'
```

`test-results/`, `build/` и `dist/` исключены из Git. Некоторые проверки требуют корпуса и аудиоустройства; их отсутствие фиксируется явным SKIP. Тестовые ролики, звук и геометрия созданы самостоятельно.

## Командная строка

```text
OpenFrame.exe [локальные медиа или проект.oframe]
OpenFrame.exe --no-api
OpenFrame.exe --no-settings --quit-after 10000
OpenFrame.exe --render-preview C:\local\preview
```

Последняя команда создаёт тестовую последовательность, проверяет команды и сохраняет снимки реального окна и JSON-отчёт. Для offscreen-проверок Windows: `QT_QPA_PLATFORM=offscreen`, `QT_QPA_FONTDIR=C:\Windows\Fonts`. Обычный запуск использует Windows backend.

`--quit-after` запрашивает закрытие; подтверждение несохранённых изменений может задержать выход.

## Форматы и сеть

Файловые операции отклоняют URL, UNC, сетевые диски и все reparse points, включая локальные symlinks/junctions. Буквальный `..` в пути запрещён; внешние относительно проекта источники сохраняются абсолютными путями. [Политика и границы проверки](docs/NETWORK_POLICY.md).

API привязан к `127.0.0.1`, использует отдельный токен экземпляра и не выполняет произвольный Python/MEL/shell-код. [Протокол и адаптер публичных методов](docs/API.md). Токены endpoint не нужно пересылать или публиковать.

## Происхождение

Приложение и ресурсы интерфейса созданы отдельно по ТЗ, публичной документации и собственным тестам. Закрытые бинарники, ресурсы и результаты прежнего анализа не передавались исполнителям реализации. [Независимая разработка](docs/INDEPENDENT_DEVELOPMENT.md), [условия библиотек](THIRD_PARTY.md).

После упаковки Build.bat создаёт рядом с каталогом пакета ZIP: dist/OpenFrame-<version>-windows-x64.zip. Версия берётся из build-info.json; внутри архива EXE и зависимости лежат в корне.


Локальные пути SDK можно сохранить в build.local.json (поля QtRoot и FfmpegRoot). Файл исключён из Git и используется перед CMakeCache.txt; параметры командной строки и переменные окружения имеют приоритет.


Перед тестами сборка автоматически создаёт отсутствующие синтетические fixtures; при изменении генераторов они пересоздаются. Нужны Python 3 и FFmpeg CLI с ffprobe (путь можно задать OPENFRAME_TEST_FFMPEG). Готовые данные остаются в test-results/fixtures вне Git. Невоспроизводимые эталонные материалы следует добавлять в tests/fixtures через LFS.


## Установка в Maya перетаскиванием

Распакуйте ZIP целиком в постоянную папку. Перетащите Install.mel из корня в viewport Maya. Установщик копирует адаптеры в пользовательскую maya/scripts, сохраняет предыдущую копию в OpenFrameBackups и создаёт вкладку Shelf OpenFrame с кнопками OF (проигрыватель) и OF Maya (синхронизация). Повторный запуск обновляет кнопки без дубликатов. После перемещения папки программы повторите установку, чтобы обновить путь кнопки OF.


Каждая сборка очищает dist целиком, включая предыдущие ZIP. Ссылки и junction в dist отклоняются; занятые файлы приводят к остановке с ошибкой. Исходники и build сохраняются.
